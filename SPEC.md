# SPEC.md — PasteWheel v1.0

Status: FINAL for build. D5 pending user confirmation; D6 provisional (see §14).

## 1. Overview

PasteWheel is a Windows clipboard utility. A radial menu ("the wheel") appears
around the mouse pointer when triggered, offering buttons that copy
pre-configured strings to the system clipboard. Buttons either copy a string
or toggle-expand into a further ring of buttons. A settings window manages all
buttons. Fully offline; no network access.

## 2. Glossary

| Term | Meaning |
|---|---|
| Wheel | The radial popup UI shown around the pointer |
| Ring / Level | L1, L2, L3 — concentric rings centered on the pointer |
| Clipboard button | Copies its configured string to the clipboard, then closes the wheel |
| Expand button | A toggle; ON shows its children evenly spaced in the next ring, OFF hides them |
| Trigger | Middle-click or `Alt+\`` |
| L1 buttons | Top-level buttons, always visible when the wheel is open |

## 4. Architecture

Single process. Qt owns the main thread and all windows. `pynput` listeners run
on background threads and communicate **only** via a Qt signal bridge
(`signals.py`) — hook threads never touch Qt widgets directly.

- `config.py` — load/validate/save `config.json`; atomic writes; corruption recovery.
- `validation.py` — all field validation rules (§9.2).
- `state.py` — wheel FSM + expand-toggle visibility rules.
- `geometry.py` — adaptive ring spacing/positions; screen clamping.
- `hooks.py` — middle-click (suppressed), `Alt+\``, `Esc` listeners.
- `wheel_window.py` — frameless, translucent, always-on-top, no-focus window.
- `settings_window.py` — settings UI incl. per-button editor.
- `clipboard_service.py`, `tray.py`, `autostart.py` — small isolated services.

## 5. State machines

**Wheel FSM:** `HIDDEN --(middle-click | Alt+\`)--> VISIBLE`;
`VISIBLE --(Esc | empty-space click | clipboard-button | gear | power)--> HIDDEN`
(power → app exit). The wheel never takes keyboard focus (FR-1.5); `Esc` is
captured by the global hook.

**Expand toggles:** each expand button is ON or OFF.
- Only one expand button per level may be ON at a time; toggling one ON
  auto-toggles its siblings OFF.
- A ring shows the children of the currently-ON expand of the previous level
  only. L2 visible ⟺ some L1 expand is ON. L3 visible ⟺ some visible L2
  expand is ON.
- All toggles reset to OFF whenever the wheel hides (FR-3.4).

## 6. UI geometry & appearance

- Wheel centered on the pointer. Buttons: circles Ø 56 px. Ring radii
  (tunable constants): L1 = 110 px, L2 = 195 px, L3 = 280 px.
- **Radial equidistant symmetry (D3):** on every ring, visible buttons are
  evenly spaced: angular gap = 360° ÷ N, where N = number of visible buttons
  on that ring. First button at 12 o'clock, clockwise. 8/16/32 are maximum
  capacities per ring (FR-2.1), not fixed layouts.
- Center: a "+" button if zero L1 buttons exist (opens settings); otherwise a
  small non-interactive dot.
- **Power & gear anchoring (Q2):** power (upper-left) and gear (upper-right)
  are fixed relative to the L1 ring's bounding box and never move, regardless
  of L2/L3 visibility. Tooltips: "Quit PasteWheel" / "Settings".
- Clicking any empty space inside or outside the wheel closes it (D2).
- **Theme (D4):** follows the Windows system theme by default; manual
  override in settings (FR-5.10). Dark and light variants fully supported.
- The whole wheel is clamped to the monitor the pointer is on.

## 7. Functional requirements

### 7.1 Triggers & lifecycle
- **FR-1.1** Middle-click anywhere shows the wheel at the pointer. The
  middle-click is swallowed system-wide **at all times**, wheel visible or not
  (browser autoscroll is permanently disabled — accepted by user).
- **FR-1.2** `Alt+\`` toggles the wheel (show at pointer if hidden, hide if
  visible). The keystroke is swallowed; focused apps never receive it.
- **FR-1.3** Middle-click while visible hides the wheel.
- **FR-1.4** Hide conditions: `Esc` (swallowed while wheel visible — the
  focused app does not receive it); left-click on empty space inside or
  outside the wheel; clicking a clipboard button (after the copy); gear click
  (then opens settings); power click (exits app).
- **FR-1.5** The wheel never takes keyboard focus; underlying apps keep focus.
- **FR-1.6** Triggers remain active while the settings window is open.

### 7.2 Wheel layout
- **FR-2.1** Ring capacities: L1 max 8, L2 max 16, L3 max 32 buttons, spaced
  per §6 (adaptive equidistant symmetry).
- **FR-2.2** L1 buttons always visible when the wheel is shown.
- **FR-2.3** Power/gear fixed positions per §6; visible in every state.
- **FR-2.4** Buttons render an emoji or ≤3-character label; hover shows a
  tooltip (configured tooltip, else the label).
- **FR-2.5** Wheel geometry is clamped on-screen on the pointer's monitor.
- **FR-2.6** First run (zero L1 buttons): only the center "+" and power/gear
  are shown; "+" opens settings.
- **FR-2.7** Every interactive control exposes an accessible name (button label or tooltip; settings fields have text labels) so UIA-based tooling can identify them reliably.

### 7.3 Button behavior
- **FR-3.1** Clipboard button click: copy its string to the clipboard, then
  hide the wheel.
- **FR-3.2** Expand button click: toggles its children ring (§5).
- **FR-3.3** L3 buttons are clipboard-only.
- **FR-3.4** All expand toggles reset to OFF when the wheel hides.
- **FR-3.5** Children of one expand: ≤16 (from L1) or ≤32 (from L2).

### 7.4 Clipboard
- **FR-4.1** Copy as Unicode text (CF_UNICODETEXT); verified readable by
  other apps.
- **FR-4.2** v1 intercepts no keyboard input other than the triggers and
  `Esc`-while-visible. Normal Ctrl+C / Ctrl+V are untouched.

### 7.5 Settings window
- **FR-5.1** Opened via gear, center "+", or tray menu. One instance reused.
- **FR-5.2** Tree of L1 buttons; expand buttons show nested children.
- **FR-5.3** Add L1 button (disabled at 8); add child to a selected expand
  (disabled at 16/32).
- **FR-5.4** Per-button editor: label; tooltip (optional); type
  (clipboard/expand — expand disabled for L3); string (clipboard only); child
  manager (expand only).
- **FR-5.5** Validation blocks saving: label must be a single emoji or 1–3
  characters (provisional, D6); clipboard buttons require a non-empty string
  (after trimming whitespace) ≤10,000 chars; expand buttons require ≥1 child;
  L3 cannot be expand. Inline error messages.
- **FR-5.6** Delete with confirmation; deleting an expand warns with the
  count of descendants that will be removed.
- **FR-5.7** Save persists `config.json` and the wheel reflects it
  immediately; Cancel discards.
- **FR-5.8** Autostart toggle (off by default) manages
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\PasteWheel`; disabled
  with an explanatory note when running from source.
- **FR-5.9** Normal window behavior (taskbar entry, resizable).
- **FR-5.10** Theme selector: System / Dark / Light; default System. Applies
  to all windows and the tray immediately on save.

### 7.6 Tray & process
- **FR-6.1** Tray icon always present while running; menu: Settings / Exit.
- **FR-6.2** Single instance: second launch shows a tray-balloon
  "PasteWheel is already running" and exits (pending confirmation, D5).
- **FR-6.3** All exit paths unregister hooks and terminate cleanly.

### 7.7 Persistence
- **FR-7.1** Config at `%APPDATA%\PasteWheel\config.json`; UTF-8,
  pretty-printed, `schema_version` field.
- **FR-7.2** First run creates a default config (zero L1 buttons → "+" state).
- **FR-7.3** Corrupt/invalid config: renamed to `config.json.bad-<timestamp>`,
  default recreated, tray notification shown.
- **FR-7.4** Writes are atomic (temp file + replace).

## 8. Non-functional requirements

- **NFR-1** Wheel visible within 150 ms of trigger.
- **NFR-2** Zero network access at runtime.
- **NFR-3** Multi-monitor and high-DPI correct (no blur, no offset buttons).
- **NFR-4** Full Unicode for labels, tooltips, strings.
- **NFR-5** Idle CPU ≈ 0% (event-driven).
- **NFR-6** Packaged build runs on machines without Python (PyInstaller,
  onedir, windowed).

### 8.1 Known limitations (documented, not fixable in v1)
- Low-level hooks receive no input over **elevated** (run-as-admin) windows
  (Windows UIPI): no wheel trigger while an admin app is focused.
- Hooks are inert on the secure desktop (UAC prompts, lock screen).

## 9. Config schema

### 9.1 Example

```json
{
  "schema_version": 1,
  "settings": { "autostart": false, "theme": "system" },
  "buttons": [
    {
      "id": "3f9c...",
      "type": "clipboard",
      "label": "TST",
      "tooltip": "Inserts test text",
      "string": "Test"
    },
    {
      "id": "8ad1...",
      "type": "expand",
      "label": "🎯",
      "tooltip": "Email snippets",
      "children": [
        { "id": "b2e4...", "type": "clipboard", "label": "HI",
          "tooltip": "", "string": "Hello," }
      ]
    }
  ]
}
```

### 9.2 Validation rules (enforced in settings and on load)
- `label`: single emoji (incl. ZWJ sequences) or 1–3 characters; non-empty.
- `string`: required iff type=clipboard; 1–10,000 chars after trim.
- `children`: present iff type=expand; count per FR-3.5; `type=expand`
  forbidden at L3.
- `settings.theme` ∈ {system, dark, light}.
- L1 array ≤ 8. Unknown fields rejected on load.

## 10. Testing strategy

**Automated gates:** `pytest -q` all green; coverage ≥ 80% on `config.py`,
`validation.py`, `state.py`, `geometry.py` (hooks/OS layer excluded by
design); `ruff check` clean. Every FR covered by ≥1 test whose name contains
the FR id (e.g., `test_fr_2_1_even_spacing`). GUI logic tested with
`pytest-qt` (`qtbot`); clipboard, registry, and system theme are mocked in
unit tests. All GUI tests must pass with QT_QPA_PLATFORM=offscreen set; the suite must not depend on the real desktop.

**Manual checklist** (OS-level behaviors, `MANUAL_CHECKLIST.md`):
MC-01 tray icon appears at startup
MC-02 middle-click shows wheel; no browser autoscroll
MC-03 `Alt+\`` toggles; `Esc` closes and is not received by the focused app
MC-04 left-click on empty space (in/outside) closes
MC-05 clipboard button copies; paste into Notepad shows exact text incl. emoji
MC-06 expand toggles on/off; sibling exclusivity; reset after hide
MC-07 power button exits fully (tray disappears)
MC-08 gear / "+" / tray all open settings; save persists across restart
MC-09 deleting an expand warns and removes subtree
MC-10 autostart toggle appears/disappears in Task Manager → Startup apps
MC-11 second monitor: wheel appears there
MC-12 high-DPI: crisp, correctly placed
MC-13 second launch: "already running" balloon, then exits
MC-14 corrupt config → default recreated, `.bad-…` file created
MC-15 theme follows Windows dark/light; manual override works
MC-16 packaged exe passes MC-01–MC-15 spot checks

## 11. Build & deploy

1. Dev run: `python -m pastewheel`.
2. Icons (tray, window, exe) come from `assets/icon.ico`.
3. Package: `pyinstaller --windowed --icon assets/icon.ico --name PasteWheel`
   (onedir). No console window.
4. `.exe` is produced **only after** MC-01–MC-15 pass on the dev build
   (user performs these).
